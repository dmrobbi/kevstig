kevstig

KEV × STIG coverage checker — a live routing table between CISA's Known Exploited Vulnerabilities catalog and the DISA STIG baselines Bedim Security maintains.

Live scoreboard → (client-side filter over a static JSON API; no accounts, no tracking) · Source repo → · Crosswalk page →

What it does

  • Fetches the CISA KEV JSON feed (honors Retry-After; a local file is also accepted) and routes each entry through mapping.json — curated, ordered, strict families.
  • Routes the platform families the estate maintains manual STIG baselines for: Windows, macOS, RHEL 8/9, Ubuntu 20.04/22.04/24.04, Firefox; the VMware estate (vSphere 6.5/6.7/7.0/8.0 as per-generation rows — a stated version routes that generation, an unstated one routes all four — plus vRealize Automation 7.x, vRealize Operations 6.x, NSX, Horizon 7.13 and Workspace ONE UEM); Citrix Virtual Apps and Desktops / XenDesktop 7.x, StoreFront, Workspace app and Receiver; and Microsoft email (Exchange Server + Outlook).
  • Counts every maintained checklist's rule ids (Vuln_Num in DISA CKL v2 format; combos with plus_ excluded).
  • Emits api/coverage.json + api/headline.json — every artifact stamps the catalog version and the generation time.
  • Gate verdict: exits nonzero unless every gate passes — prints KEVSTIG-OK catalog=<n> routed=<n> uncovered=<n> for automation.

What it does NOT do

Routed is NOT remediated. DISA manual STIGs harden configuration; they do not patch individual CVEs. Nothing here claims a rule neutralizes a specific CVE — the STIG XMLs parsed here carry no CVE references (verified: 0 hits).

The gap is the artifact. The uncovered count is published on purpose: appliances, web apps, middleware and network gear with no maintained baseline (NetScaler, ShareFile, SD-WAN, Session Recording, WS1 Access, the VMware Tools/Spring multi-product bundles), listed plainly. It feeds the crosswalk work.

Generic-family entries ("Linux Kernel", vendor bundles) stay uncovered in v1 on purpose: the routing table matches products literally, never guesses. Red Hat middleware like JBoss deliberately does not route — only OS-surface components do. Empty-platforms guard families deliberately exclude lookalike products. The RHEL 7 EOL track was retired from the maintained set (owner call, 2026-10-06) — its baseline lives under baselines/archive/ in stig-baselines.

Quickstart

git clone https://github.com/dmrobbi/kevstig.git && cd kevstig
make                                   # build into /tmp/kevstig-deploy
python3 kevstig.py --kev kev.json \
  --baselines <stig-baselines>/baselines --out /tmp/x

make produces the deployable set (page + API JSONs). The scorer is also runnable standalone as shown. Corrections to the routing table are welcome as pull requests.

Methodology (dated)

  • Release: v0.1.0, tagged 2026-10-19, with a dated CHANGELOG.
  • Method: strict-literal product routing (no fuzzy family guessing), per-generation VMware rows, explicit exclusion guards for lookalike products; rule counts read from generated CKLs' Vuln_Num ids only.
  • Catalog: CISA KEV JSON, re-fetched each daily refresh; artifacts carry the catalog version + generation time.
  • History: built 2026-10-03 from the publicity-casebook research corpus; 2026-10-05 the routing extended to the full VMware family + Citrix + Microsoft email (fc0e040..b3751d4); 2026-10-06 the RHEL 7 EOL retirement (scoreboard: 21 platform rows / 6,431 rules).
